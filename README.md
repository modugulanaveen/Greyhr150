# PayMate — Phase 10

Production-oriented, multi-tenant Indian Payroll Management SaaS. Phase 10 extends the complete Phase 1–9 payroll workspace with production hardening, administration, tenant security, settings and SaaS-ready foundations.

## Included phases

- **Phase 1:** Supabase Auth, company onboarding, tenant-aware workspace, responsive dashboard/navigation.
- **Phase 2:** Employee CRUD, departments, employee documents/private Storage, sensitive-data restrictions, Excel export.
- **Phase 3:** Salary structures, configurable PF/PT settings, pure salary calculation engine, effective-dated salary revisions/history, employee salary integration, dashboard salary metrics and Excel export.
- **Phase 4:** Monthly attendance, LOP management, calendar/working-day proration, joining-date proration, adjusted Basic/Special/Gross, PF/PT after LOP, Excel import/export, attendance settings, attendance history and LOP audit logs.
- **Phase 5:** Financial-year tax configuration, projected current-employer salary, previous-employer taxable salary/TDS, progressive slabs, Section 87A rebate, marginal relief, cess, first-month deferred TDS, monthly schedules and whole-rupee reconciliation.
- **Phase 6:** Monthly payroll runs, salary/attendance/TDS integration, payroll validation, manual adjustments, reconciliation, review/approval/lock/reopen workflow, immutable payroll snapshots, payroll history and Excel export.
- **Phase 7:** Payslip management, A4 PDF generation, private Supabase Storage, payroll-snapshot payslips, versioned regeneration, secure signed downloads, controlled bulk generation, ZIP downloads, company branding/settings and payslip audit actions.
- **Phase 8:** Statutory compliance, PF/ECR preparation, PT/TDS compliance reports, statutory liabilities/payments, effective-dated rules and private compliance exports.
- **Phase 9:** Payroll dashboard, analytics, payroll/employee/salary/attendance/deduction/employer-cost reports, reusable filters, pagination, column visibility and authenticated Excel exports.
- **Phase 10:** Production configuration, security hardening, settings, user management, role/permission review, audit immutability, private storage controls, rate limiting, health checks, subscription-ready structures, usage tracking and deployment/recovery documentation.

## Phase 3 salary calculation

The calculation engine is pure and reusable at:

```text
packages/shared/src/payroll.ts
apps/web/src/modules/payroll/calculations/
```

All displayed payroll values use `roundPayrollAmount()` and are whole rupees.

### Basic Salary

Default settings:

- Minimum Basic: ₹20,000/month
- Basic Percentage: 50%
- Employee PF: 12%
- Employer PF: 12%
- PF wage ceiling: ₹25,000

For monthly CTC:

```text
if Monthly CTC <= Minimum Basic × 1.12
    Basic = Monthly CTC / 1.12
else
    Basic = MAX(Minimum Basic, Monthly CTC × Basic Percentage)
```

The calculation uses whole-rupee rounding for payroll display/calculation.

### PF

```text
PF Wage = MIN(Basic Salary, PF Wage Ceiling)
Employee PF = PF Wage × Employee PF Rate
Employer PF = PF Wage × Employer PF Rate
```

Rates and ceiling are stored per company in `pf_settings` and can be changed by authorized company administrators/HR.

### Special Allowance

```text
Special Allowance = MAX(0, Monthly CTC - Basic Salary - Employer PF)
```

There is no minimum ₹5,000 allowance rule.

### Professional Tax

PT is configurable by company using state and ordered slab rows in `pt_settings`. Phase 3 deliberately does not hard-code one statutory amount for every Indian state. The default configuration is an editable example slab so the calculator can produce a PT value immediately; companies should configure the applicable state/slabs before relying on payroll output.

### Net Salary and employer cost

```text
Gross = Basic + Special Allowance
Estimated Net = MAX(0, Gross - Employee PF - PT)
Total Employer Cost = Monthly CTC
```

TDS, monthly payroll approval/locking, payslips, ECR and bank transfer files are **not** implemented in Phase 4.

### Monthly proration

For Calendar Days:

```text
Daily basis = Monthly salary / Calendar days in month
Eligible days = Joining date through month end
Paid days = Eligible days - LOP days
```

For Working Days, weekly offs and configured holidays are excluded from the divisor and eligibility window. LOP never changes the permanent salary structure; it only changes the monthly payroll preview.

Adjusted Gross is calculated from the permanent monthly gross multiplied by the paid-day ratio, rounded centrally. Adjusted Basic is rounded separately and Special Allowance is the balancing component so the adjusted earnings reconcile exactly to Adjusted Gross.

## Phase 5 — TDS & Income Tax

Route:

```text
/tds
```

Phase 5 adds a configurable Indian salary TDS estimation/withholding engine. It is **not a tax-return filing system**.

Capabilities:

- Financial-year and tax-regime selection
- Current-employer annual salary projection using Phase 3 effective-dated salary structures and Phase 4 attendance/LOP records
- Joining-date and salary-revision-aware projection
- Previous Employer **Taxable Salary** and previous employer TDS
- Other taxable income and other income TDS
- Financial-year-specific standard deduction
- Progressive configurable tax slabs
- Configurable Section 87A rebate
- Separate marginal-relief calculation
- Health & Education Cess
- Exact whole-rupee annual TDS reconciliation
- First-month Full Monthly or Prorated + Redistribute TDS method
- Final-month rounding adjustment
- Monthly TDS schedule
- Employee TDS table and annual tax detail
- Tax configuration at `/settings/tax` for authorized administrators
- Excel TDS export
- Employee TDS detail route at `/employees/:employeeId/tds`

### Phase 5 migrations

Run after the Phase 1–4 migrations:

```text
supabase/migrations/202609300005_phase5_tax.sql
```

The migration creates company-scoped `tax_settings`, `tax_slabs`, `tax_rebates`, `employee_tax_profiles`, `tds_calculations` and `tds_monthly_schedule` tables with RLS and employee/company integrity triggers. It also seeds configurable reference values for FY 2025-26 and FY 2026-27. Verify statutory values for the applicable financial year before relying on payroll output.

### Tax calculation architecture

The reusable tax engine is in:

```text
packages/shared/src/tax.ts
apps/web/src/modules/tax/
```

The annual engine combines previous-employer taxable salary, current-employer projected salary and other taxable income. The standard deduction is applied once to the current-employer salary component; **Previous Employer Taxable Salary is not reduced by the standard deduction again**.

LOP and salary revision projection are reused from the existing Phase 4 attendance and Phase 3 salary structures rather than duplicating those formulas.

### TDS allocation

The reusable allocation function supports:

```text
FULL_MONTHLY
PRORATED_REDISTRIBUTE
```

For `PRORATED_REDISTRIBUTE`, first-month withholding is reduced according to eligible payroll days and the deferred balance is distributed across the remaining payroll months. The final month receives any whole-rupee reconciliation adjustment so the schedule sum exactly equals the recoverable annual TDS.

### Tax safety

Tax rates, slabs, rebates, standard deduction, cess and marginal-relief thresholds are database configuration rather than React constants. This application estimates payroll withholding; it does not file income-tax returns or generate statutory filings.

### Payroll snapshot and immutability

Approval and locking preserve calculated payroll values in `payroll_records`. Future salary revisions, attendance changes or TDS recalculations do not rewrite a locked historical snapshot through the payroll workflow. Locked runs can only be reopened by `OWNER` or `COMPANY_ADMIN`, with a required reason recorded in `payroll_audit_logs`.

### Payroll reconciliation

The shared payroll-run calculation service uses the existing Phase 4 preview and centralized whole-rupee rounding. Backend reconciliation verifies:

```text
Adjusted Gross + Adjustment Earnings
- Employee PF - PT - TDS - Other Deductions - Adjustment Deductions
= Net Salary

Adjusted Gross + Adjustment Earnings + Employer PF
= Employer Cost
```

Approval is blocked when unresolved payroll validation errors exist or totals fail reconciliation.

## Phase 7 — Payslips

Routes:

```text
/payslips
/payslips/:payslipId
/payslips/settings
```

Payslips are generated only from APPROVED or LOCKED Phase 6 payroll runs. The PDF service reads `payroll_records` as the salary/attendance/TDS snapshot and does not recalculate salary, attendance, PF, PT or TDS. A `snapshot` JSON object preserves employee/statutory/branding display data for each generated version so later employee or company-setting changes do not silently rewrite an historical payslip.

### Private storage

Phase 7 creates two private Supabase Storage buckets:

```text
payslips
payslip-branding
```

Payslip PDFs are stored under:

```text
company/{companyId}/{financialYear}/{YYYY-MM}/{employeeId}/v{version}/PAYSLIP_{EmployeeID}_{YYYY-MM}.pdf
```

Downloads use short-lived signed URLs generated by the backend. The service-role key is never exposed to the browser.

### PDF and ZIP generation

The API uses PDFKit for real A4 PDF documents and Archiver for server-side ZIP creation. Bulk generation is capped at 500 records per request and processes records sequentially to avoid uncontrolled browser concurrency.

### Payslip settings

Company administrators can configure branding, footer text, PAN/UAN/bank display and masking at `/payslips/settings`. Logos accept PNG, JPG/JPEG and WEBP up to 2 MB and are stored privately.

### Payslip API

```text
GET  /api/payslips
GET  /api/payslips/:id
POST /api/payslips/:id/generate
POST /api/payslips/generate
GET  /api/payslips/:id/download
GET  /api/payslips/bulk/download
GET  /api/payslips/settings
PUT  /api/payslips/settings
POST /api/payslips/settings/logo
```

Generation is limited to OWNER, COMPANY_ADMIN and HR. ACCOUNTANT can view/download authorized company payslips under the existing company-access model. Every protected operation verifies Supabase Auth and company membership.

### Historical integrity

Payslip regeneration creates a new `version` and keeps the prior generated record. Old PDFs are not overwritten. If a payroll is later reopened and recalculated, a newly generated payslip version reflects the new payroll snapshot; an earlier generated version remains tied to its original snapshot.
